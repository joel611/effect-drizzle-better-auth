# Effect-ts tutorial

## Goal

Learn Effect-ts's dependency-injection model by building small, real service around Drizzle ORM (Postgres) and Better Auth.

- Effect-ts Dependency Injection — model app dependencies (DB client, auth client, config) as `Context.Tag`s instead of manual wiring or singletons.
- Service and Layer — define services as Effect `Service`s and compose their dependencies with `Layer` (e.g. a `Db` layer wrapping a shared `pg.Pool` + Drizzle, an `Auth` layer wrapping Better Auth over the same pool).
- Test mock — swap real Layers (Postgres, Better Auth) for in-memory/test Layers in tests, without touching business logic, to see how Effect's DI makes services testable in isolation.

## Component

- effect@v4 (https://effect.website/docs/v4/)
- drizzle-orm/node-postgres
- better-auth

## Reference

- Drizzle node-postgres (https://orm.drizzle.team/docs/get-started-postgresql#node-postgres)
- Better Auth Drizzle adapter (https://www.better-auth.com/docs/adapters/drizzle)

## Layout

- `packages/core` — the one shared package; `drizzle-kit` config (`drizzle.config.ts`) and generated migrations (`drizzle/`) live at its root
  - `src/libs/db` — the `Db` Effect Layer (one `pg.Pool` + `drizzle-orm/node-postgres`, acquired and released as a scoped resource); `schema.ts` defines `task` and re-exports the auth tables so `drizzle-kit` sees one combined schema
  - `src/libs/auth` — Better Auth wrapped as the `Auth` Effect service, using Better Auth's official `drizzleAdapter` over the same shared `Db` pool; owns `auth-schema.ts`, generated by the Better Auth CLI (see `auth.config.ts`)
  - `src/demo-feature` — the demo feature: `TaskRepository` built on top of `src/libs/db`, with its own tagged errors in `error.ts`
- `apps/server` — `Bun.serve` entrypoint wiring services into HTTP routes (tasks, and Better Auth under `/api/auth/*`)

## Getting started

```sh
cp .env.example .env
docker compose up -d --wait
bun install
bun run db:migrate
bun run dev
```

- `bun run typecheck` / `bun run test` / `bun run lint` / `bun run fix` — run across every package via turborepo
- `bun run db:generate` — generate a new migration after editing `packages/core/src/libs/db/schema.ts`
