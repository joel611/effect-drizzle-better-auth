# Drop `@effect/sql-pg` for `Db`; build one shared `pg.Pool` so Better Auth's official `drizzleAdapter` can use it

`@effect/sql-pg`'s `PgClient` has no way to accept an already-constructed `pg.Pool`, and `drizzle-orm/effect-postgres` is hard-typed to `@effect/sql-pg`'s own `PgClient` service, not a generic `SqlClient`. Better Auth's official `drizzleAdapter` runs queries with `await db.select()...`, which only works against a plain, promise-returning Drizzle instance — not `drizzle-orm/effect-postgres`'s Effect-returning query builders. So the app's own queries and Better Auth's stock adapter could not share one Postgres connection pool while `Db` stayed on `@effect/sql-pg`.

This supersedes [ADR 0001](./0001-pg-based-postgres-client-over-bun-sql.md) and [ADR 0002](./0002-pin-drizzle-rc5-dist-tag-drop-sql-drizzle-bridge.md)'s rationale for choosing `@effect/sql-pg` + `drizzle-orm/effect-postgres`: that reasoning assumed a repo without this pool-sharing requirement. `Db` (`packages/db/src/client.ts`) is rebuilt over a plain `pg.Pool` and `drizzle-orm/node-postgres`, constructed once via `Effect.acquireRelease` and exposed through `Layer.effect` (Effect's layer builders run scoped effects in the layer's own scope, so no separate `Layer.scoped` call is needed). `TaskRepository`'s query chains, now promises again, are wrapped individually in `Effect.tryPromise` at the call site — the promise boundary this repo studies moves into our own domain code instead of living only inside a Better Auth adapter. `AuthAdapter` (`packages/auth/src/auth-adapter.ts`) builds Better Auth's official `drizzleAdapter` directly over the same `Db` instance, so both consumers resolve to the exact same `pg.Pool` object through Effect's layer memoization — verified directly in `packages/auth/src/shared-pool.test.ts` by comparing `db.$client` with a `pool` handle `AuthAdapter` exposes alongside its adapter.

Trade-off accepted: `Db`'s query builders are plain promises again, not native Effects, so `@effect/sql-pg`'s Effect-native ergonomics are lost for the sake of a genuinely shared pool. No custom Better Auth adapter, `where`-clause translator, or hand-carried transaction context is needed — Better Auth's official adapter owns its own transaction handling against the plain driver.
