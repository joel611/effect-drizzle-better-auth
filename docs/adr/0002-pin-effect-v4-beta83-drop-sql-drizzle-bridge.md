# Pin effect + @effect/sql-pg to 4.0.0-beta.83, not the newer rc tag; use Drizzle's native effect-postgres adapter, not @effect/sql-drizzle

`effect` and `@effect/sql-pg` are pinned to the exact `4.0.0-beta.83` release in the root `package.json` catalog, deliberately behind the `rc` dist-tag (currently `4.0.0-rc.115`). `drizzle-orm@1.0.0-rc.4` was built and tested against `effect@4.0.0-beta.83`; installing against `rc.115` breaks at runtime (`Schema.TaggedErrorClass is not a function`) because a Schema export drizzle-orm's cache module depends on was renamed/removed between those two pre-release lines. Confirmed with a throwaway spike before scaffolding: `rc.115` fails, `beta.83` round-trips cleanly. Bumping `effect`/`@effect/sql-pg` to a newer tag later requires re-verifying against whatever `drizzle-orm` version is current at the time, not just taking the latest `rc`.

Separately, we don't use the `@effect/sql-drizzle` bridge package at all — it peers on `effect@^3.22.0` (v3, incompatible with the v4 line this repo is built on) and is superseded by Drizzle's own first-party `drizzle-orm/effect-postgres` adapter (`PgDrizzle.makeWithDefaults()`), which is what `packages/db/src/client.ts` uses directly against `@effect/sql-pg`.
